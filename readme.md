# 开发状态

## ✅ 目前正在做的

- **v4.4.0 ~ v4.7.0 四批更新已完成**（详见下文各版本章节）。
- **Kotlin 重构已完成**：`app/src/main/java` 下全部 Kotlin、0 个 Java 文件；网络层已升级 **okhttp 4.x**。
- **播放器稳定性**：时间显示不同步、退出卡死、播放器重复打开、弹幕补拉卡顿等问题均已修复，看门狗自动恢复兜底。

## 🆕 v4.7.0（20261023）—— 大改动批次

- **图片双指缩放手势优化**（图片查看页）：
  - 缩放倍率改为三档（**1x / 2.5x / 8x**），捏合到中档附近自然吸附，不再只有"最小/最大"两档；
  - **多指手势期间左右翻页不再抢手势**：原实现在 `dispatchTouchEvent` 里临时放开拦截标志，恰好会让 `onInterceptTouchEvent` 生效，于是"放大到一半突然跳页/回弹"；现在多指一律不拦截，缩放能完整做完；
  - 双击缩放动画缩短到 200ms，手感更跟手；并保留抬指瞬间指针越界的异常兜底，避免偶发崩溃。

- **弹幕卡死 / 按钮关了弹幕还在**（播放器）：
  - **重开弹幕按钮 = 整条获取流程从头走一遍**：中断旧拉取 → 重建弹幕层 → 重新拉取全部分段（直播走空弹幕层，本地弹幕重新加载文件）；
  - **关闭弹幕立即清屏**：除 `hide()` 外还在 UI 线程直接触发画布清空，不再依赖可能已卡死的绘制线程，修掉"按钮已经关了、弹幕还留在屏幕上"；
  - **切回前台做健康检查**（绘制 handler 是否还存在），不健康就整条重建，修掉弱网下"切后台再切回来弹幕卡死"；（判据刻意不用 `handler.isStop` —— 暂停播放时它本来就是 `true`，用它会导致每次暂停后切回都白拉一遍全部弹幕）
  - **重建的释放动作移到后台线程**：`release()` 会 join 绘制线程、弱网下可能阻塞数秒，放在主线程会变成新的"点一下卡半天"。

## 🆕 v4.6.0（20261022）—— 小改动批次

- **播放器时间不动（一直是 00:00）修复**：进度时间文本此前只在"用户拖动进度条"这一条路径上刷新（`onProgressChanged` 内仅 `fromUser` 时写），播放过程中的定时刷新完全没有更新它，因此永远停在布局初始值 `00:00/00:00`；现在由进度定时器直接驱动，控制栏收起时也保持约 1 秒的低频刷新。
- **弹幕时间跳转重做**：
  - **去掉**弹幕出现时间戳时弹出的巨大 Toast（严重干扰视野）；
  - 弹幕文本里的时间戳渲染为**蓝色 + 下划线**，一眼可辨；
  - **轻点**该弹幕即可跳到对应时间；
  - 新增播放器设置开关 **「弹幕时间跳转」**，关闭后不标记、不响应点击。
- **跳转弹窗入口收敛**：底部收起状态下的时间文本不再弹出跳转小窗；只有**控制栏展开时的左侧进度时间**与**右侧收缩栏的时间按钮**可以打开。
- **时间输入分隔符**：空格、中文冒号（：）、英文冒号（:）都作为分隔符且可混用 —— `5 30` 与 `5:30`、`5：30` 等价，仍支持 `90`（秒）与 `01:02:03`（时:分:秒）。

## 🆕 v4.5.0（20261021）—— 大改动批次

- **双列模式适用于所有视频列表**：实验室「视频列表双列模式」的覆盖范围从少数页面扩展到**全部视频列表**——推荐、热门、排行、入站必刷、推荐直播、关注直播、搜索结果（视频/直播）、收藏、历史、稍后再看、追番、UP主投稿、UP主系列、合集详情、视频相关推荐，统一使用信息流卡片（封面撑满+标题不省略），方屏/大屏手表一屏可见更多视频；设置、消息等非视频列表不受影响。
- **弹幕太多卡顿修复**：
  - 缺失分段的后台补拉回调不再在主线程解析（弱网下多段集中到达时，整段几百条弹幕的解析与投递曾直接卡死 UI），改为后台线程执行；
  - 新增**同屏弹幕数量硬上限**（默认 30 条，设置键 `player_danmaku_maxinscreen`），密集弹幕时超出部分按优先级丢弃，绘制压力可控。

## 🆕 v4.4.0（20261020）—— 播放器体验修复

- **播放时间与进度条同步修复**：
  - 控制条隐藏期间进度条改为约 1 秒低频刷新——之前完全停更，呼出进度条看到的是旧位置，要等下一个周期才"跳一下"；
  - 修复进度条拖动被手表触摸手势打断后**时间文本永久冻结**的问题；
  - Surface 重建（切后台回来等）不再把视频**跳回旧时间**；
  - 修复部分视频刚打开时**总时长显示 00:00、进度条错乱**的问题（DASH 流刚 prepare 时拿不到时长）。
- **弹幕时间戳跳转**：弹幕里出现 `8:17`、`1:02:03` 这类时间戳时，点击进度时间文本会先提供「跳到弹幕提到的时间」的快捷项（解析带边界校验，比分 `3:2` 不会误判）。
- **播放退出卡死修复**：播放器 `stop`/`release` 等耗时 native 调用、弹幕层释放、缓存清理全部移到后台线程，弱网缓冲中退出瞬间不再卡住返回。
- **时长显示 "null" 修复**：动态/搜索番剧卡片等处的播放量、时长信息不再显示字符串 "null"。
- **播放器不会重复打开**：播放按钮 800ms 去抖 + 防重入标志；播放器 Activity 改 `singleTask`，连续点击只会进入一个播放器。

## 🆕 v4.3.0（20261019）—— 大改动批次

- **双列模式收敛为视频列表专属**：普通列表一律单列；视频卡片列表的双列改用信息流布局——封面撑满卡片、标题在封面下方不省略、卡片高度自适应；**横屏模式整体删除**（含设置开关与三列布局）。
- **表冠滑动过快修复**：步长减半、单档上限 120px→40px，并加 33ms 时间片配额限速，快速连转不再"微微一转滑出半屏"。
- **时间调节小窗**：播放页右侧折叠栏新增「调节进度」按钮，弹出与发送弹幕同款小窗——可输入 `90` / `1:30` / `01:02:03`，也可直接转表冠 ±5s 微调并回填输入框。
- **拉流策略（替代高温预缓存）**：实验室新增选择——①慢速持续拉取（原行为，稳定，4G 耗电发热）②脉冲式（快速拉一段→停→循环，4G 不发热但可能偶卡）。
- **缓存断点续传 + 自动重试**：下载带 Range 从断点续传，网络错误自动重试最多 5 次（线性退避）。
- **清理与依赖升级**：删除无用代码；okhttp 3.12.1 → **4.11.0**（3.x 已 EOL），全项目 API 迁移。

## 🆕 本轮更新（弹幕与播放体验专项）

- **关闭开屏动画**：移除开屏页逐字打字机的 100ms 轮询定时器与进入延时，启动阶段不再做无谓的 UI 刷新，直接显示完整文案并立即跳转。
- **抗网络波动 · 弹幕不再丢失**：
  - 新版弹幕接口改为**逐段重试 + 指数退避**，任一段失败只登记为"缺失"，不再中断后续分段，也不会因为一个空分段就丢掉后面全部弹幕；
  - 已到达的分段**边下边渲染**（不再等全部拉完），失败分段交给后台补拉器按退避持续补齐，补到即增量追加；
  - 弹幕层 `prepare()` 是异步的，先于它就绪的分段会**暂存**而不是被静默丢弃，`prepared()` 回调时统一补渲染；
  - 直播弹幕 WebSocket 断线后**指数退避自动重连**，不再"断一次就永久没有弹幕"；心跳定时器改为单实例，重连不再累积泄漏。
- **抗网络波动 · 视频不再卡死**：
  - 新增播放**卡死看门狗**（`PlaybackWatchdog`）：同时监测"缓冲超时"和"进度长时间不推进"两种 ijkplayer 假死（这两种情况都不会触发 `onError`），命中后自动重建数据源并**跳回原进度**继续播放，最多自动恢复 3 次；
  - 开启 FFmpeg 层 `reconnect` / `reconnect_streamed` 断线重连，并加大默认播放缓冲（5MB→20MB），提升抖动容忍度；
  - 修复卡死恢复路径上的 Surface 回调与 Timer 重复累积问题。
- **性能与发热优化**：
  - 弹幕层重绘频率由固定 60fps 降为**默认约 30fps**（新增设置项"弹幕刷新间隔(ms)"，可 16~66 自行调节），重绘次数减半；
  - protobuf 弹幕解析的反射查找改为**按 Class 缓存 Field**，一个视频上万条弹幕不再重复反射，解析开销大幅下降；
  - 进度轮询里的字幕计算移出主线程、`MediaSession` 状态更新由 250ms 降为 1s、字幕可见性避免重复 `setVisibility`；
  - 修复 `showLoadingSpeed` / `progressChange` / `onlineChange` 三个定时器在缓冲、自动恢复、切P时**重复创建不取消**的泄漏。
- **新增开关**：「低延迟优先」（用抗抖动换低延迟，默认关闭）、「弹幕刷新间隔」。
